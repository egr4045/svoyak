# Боты тестового режима

Заменяют предпросмотр настоящей игрой: тот же `GameState`, те же хендлеры, те же таймеры —
просто вместо живых людей боты. Включается через `POST /api/rooms/test`.

## Почему фейковый сокет, а не прямые вызовы GameState

Логика баззера живёт **не** в `GameState`, а инлайном в сокет-слое:
`roomHandlers.js` — отсчёт 3с, анти-чит-кламп, окно сбора откликов 5с, `buzzer_results` 3.5с.
Бот, зовущий `room.handleAction('player:pressBuzzer')`, туда просто не попадёт.

Поэтому бот получает `botSocket.js` — 25-строчный шим, на который вешается настоящий
`handleRoomEvents`. Итог: прод-хендлеры не тронуты вообще, а бот проходит ровно тот же путь
и те же гварды (`isPlayer()`, `isHost`, анти-чит), что живой игрок. Для *тестового* режима
это и есть весь смысл.

## Планировщик (`BotDriver.js`)

Хук — единственная точка рассылки, `GameState.broadcast`. Бот реагирует на смену состояния
так же, как живой клиент реагировал бы на `gameStateUpdated`.

Ядро: **ключ таймера кодирует своё собственное предусловие**.

```
key = `${actorId}|${action}|${round}:${cat}:${q}:${status}${дискриминатор}`
```

- ключ пропал из нового плана ⇒ действие протухло, таймер снимается;
- ключ уже вооружён ⇒ не перезаводим (чужой сабмит не сбрасывает чужую задержку реакции);
- при срабатывании план пересчитывается, и `run()` вызывается, только если ключ ещё актуален.

⚠️ **Дискриминатор выводим только из состояния.** Случайный выбор в ключе делает действие
самоотменяющимся: `run()` пересчитает план, вытянет другой рандом и не найдёт свой ключ.
Случайность — внутрь `run()`. На этом уже споткнулись дважды (выбор ячейки и исполнителя).

Предохранители: бюджет 60 действий / 10с (превышение ⇒ `detach`, замершая игра вместо
busy-loop), холостой пульс раз в 20с (не все хендлеры делают broadcast), заморозка плана,
когда в комнате нет живых, и правило `stuck` в `hostBrain` — аварийное закрытие вопроса,
если ни одно правило не сработало.

## Что боту можно знать

Только то, что видит человек на его месте: разосланный стейт + свой приватный показ.
Приватный показ по сети до фейк-сокета не доходит (`io.to('bot:p1')` — несуществующая
комната), поэтому читаем эквивалент из `room.privateReveal` / `room._priv` напрямую.

Три осознанных исключения, где честность даёт бессмысленный шум вместо проверки механики:
`reaction` (иначе случайный тык), `number` (иначе таблица «кто ближе» — мусор), `among_us`
(иначе шпиона не находят никогда). Не читерят: «кто сказал», тир-лист, камень-ножницы.

## Файлы

| Файл | Что внутри |
|---|---|
| `BotDriver.js` | планировщик: план → таймеры → перепроверка, бюджет, пульс |
| `hostBrain.js` | ведущий-бот: таблица `questionStatus` → действие (зеркало `HostPanel.primary`) |
| `playerBrain.js` | игроки-боты: баззер, выбор ячейки, сабмиты и голосования по типам |
| `botSocket.js` | шим сокета под настоящий `handleRoomEvents` |
| `testRoom.js` | создание комнаты, рассадка, срез пака до одной ячейки |
| `personas.js` | характеры: `skill` (как часто знает ответ), `speed` (множитель задержек) |
| `judge.js` | автосудейство письменных ответов (регистр, ё, опечатки, подстрока) |
| `canned.js` | неверные ответы, отговорки шпиона, фразы «кто сказал», SVG-каракули |
| `rng.js` | детерминированный ГПСЧ от кода комнаты — прогон воспроизводим |

## Как менять

Добавили статус в игру — добавьте ветку в `hostBrain.plan` и, если игрок там что-то делает,
в `playerBrain.plan`. Проверка одна: `server/tests/bots/fullGame.test.js` требует `game_over`
на 20 разных сидах **и ноль срабатываний `stuck`**. Если `stuck` вырос — статус не разобран.
